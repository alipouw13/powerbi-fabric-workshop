# Lab 2 - Data Modeling

**Duration:** ~75 min - **Deck:** "Data modeling: the star schema"

You will replace the wide Tableau-style extract with a Power BI star schema. This is the single biggest quality lever for performance, usability, Copilot quality, and trusted measures.

## Schwab context
A flat Tableau extract can be fast to start, but it often hides business logic in workbook calculations. For Schwab-scale analytics, Power BI works best when shared dimensions and facts are modeled once and reused by many reports.

You will import the star-schema CSVs generated in Lab 0 and create a clean model with single-direction filtering. The goal is to make the data easier for analysts, executives, and AI features to understand.

## What you'll build
- A Power BI model using redfin/fact_home_sales.csv.
- Dimension tables from redfin/dim_region.csv, redfin/dim_date.csv, and redfin/dim_property_type.csv.
- Relationships from fact_home_sales to the dimensions with single-direction filtering.
- A marked date table using dim_date[period_begin].
- Hidden key columns and friendly business names.
- A short comparison between the wide extract and the star schema.

## Prerequisites
- Completed [Lab 1 - Tableau to Power BI](../lab-01-tableau-to-powerbi/README.md).
- Local files under data/raw/redfin/ generated by Lab 0.
- Power BI Desktop with access to Power Query, Model view, and Report view.
- Concept reference: [reference/tableau-to-powerbi.md](../../reference/tableau-to-powerbi.md).

## Steps
### 1. Save a new modeling file
Open Power BI Desktop and save a new file named Housing-Star-Model.pbix.

This keeps the quick extract tour from Lab 1 separate from the reusable model you are about to build.

### 2. Review the wide extract one more time
Open data/raw/redfin/market_tracker.csv outside Power BI.

Notice that region attributes, date attributes, property type, and facts are all repeated in one table. That is common in Tableau extract workflows, but it makes shared Power BI models harder to govern.

### 3. Import the star tables
Use Get data -> Text/CSV to import these four files:

- data/raw/redfin/fact_home_sales.csv
- data/raw/redfin/dim_region.csv
- data/raw/redfin/dim_date.csv
- data/raw/redfin/dim_property_type.csv

Load them into the model. Do not load market_tracker.csv into this file.

### 4. Confirm data types
In Power Query or Data view, check the important types.

Set dim_date[period_begin] as Date, fact_home_sales numeric columns as whole number or decimal number, and key columns as whole number or text based on the generated files.

### 5. Create the relationships
Open Model view and connect fact_home_sales to each dimension.

Create relationships from fact_home_sales[region_id] to dim_region[region_id], fact_home_sales[date_id] to dim_date[date_id], and fact_home_sales[property_type_id] to dim_property_type[property_type_id]. Use many-to-one cardinality and single direction filtering from each dimension to fact_home_sales.

### 6. Mark the date table
Select dim_date and mark it as the date table.

Use dim_date[period_begin] as the date column. This helps time intelligence, DAX, and Copilot understand that dim_date is the calendar table.

### 7. Hide technical keys
Hide region_id, date_id, property_type_id, and other join-only columns from Report view.

Keep business columns visible, such as region, state, month_name, year, property_type, median_sale_price, homes_sold, inventory, and months_of_supply.

### 8. Set friendly names and formats
Rename fields so report authors see business language.

Examples: median_sale_price to Median Sale Price, homes_sold to Homes Sold, median_days_on_market to Median Days on Market, and avg_sale_to_list to Avg Sale to List %. Set currency, whole number, and percentage formats where appropriate.

### 9. Add draft validation measures
Create a small Measures table or use fact_home_sales for draft measures.

Add Homes Sold as the sum of homes_sold and Avg Median Sale Price as the average of median_sale_price. You will formalize the complete measure set in [src/pbip/README.md](../../src/pbip/README.md) during Lab 6.

### 10. Validate the model with a simple visual
Create a temporary report page with region on rows and Homes Sold as the value.

Add property_type as a slicer and confirm that filtering behaves as expected. If a slicer does not affect the visual, return to Model view and check the relationship.

## You'll know it worked when
- Housing-Star-Model.pbix contains fact_home_sales, dim_region, dim_date, and dim_property_type.
- The three dimension relationships are active and single direction.
- dim_date is marked as the date table using period_begin.
- Technical keys are hidden from Report view.
- You can explain why this star schema is better than one wide Tableau extract.
